# 1.3.0：原应用图标与同任务导航交接

本版 APK code39，仪表仍使用 **1.2.0 配套 App**，没有新仪表二进制改动。已装1.2.0仪表者只覆盖安装同签名APK；更早版本需要先更新仪表App。提供配套FULL时，仪表ZIP保持1.2.0原字节和原文件名，不把换名当成新固件。MCU/参考OS/Boot/USB角色和视频路线均不改。

## 交互

1. 在原地图中规划路线或开始导航，再到Dashcast选择该应用、开始投屏；已有任务按ID采纳，不再发一次启动Intent。地图未运行时才使用现有的已核对冷启动入口。
2. 投屏中点击车机桌面的**原应用图标**。车机进入同一个地图任务，可操作路线；仪表继续显示此任务。无需另装查看器、替代图标或使用“打开投屏应用”入口。
3. 车机切换到音乐等其他应用，原地图任务进入Dashcast自有副屏继续绘制。返回原地图图标时，同一任务返回主屏；不是两份独立导航，主屏操作会反映到仪表。
4. 停止投屏只归还原任务并关闭所属采集资源，不强停/删任务/重发导航Intent。地图应保留当前导航；再开始应可继续使用同一任务。

主屏共显采用主屏取景比例；副屏采用仪表布局比例，跨屏时地图会重新排版。调整裁剪后需停止再开始。原图标交接只适用于具体应用和目标系统支持的跨屏任务；secure界面、多个同包任务或归属不明会明确失败，不猜任务、不以其他应用画面顶替。

## 实现与保护

- 新Kotlin任务适配、路由、原入口事件匹配、自有显示缓冲和编码切源门控。精确绑定当前user/task/root，移动stack前确认仅有该任务；不能把主屏其它任务一起迁走。
- 原高德图标可能先创建UsbFill再转主地图，因此处理OEM两个固定事件`am_create_activity/am_new_intent`。仅处理所选应用的已核对原入口MAIN事件或该任务的MAIN事件，不采纳深链/内部无action事件；不存全量系统日志、URI/MIME或记录地图内容。
- 编码器输入由独有SF镜像跟随已确认来源，副屏另有持续释放的自有缓冲；不将两个生产者接同一编码Surface。切源后丢弃旧时间戳/P帧，等新IDR再传，同一个AVC/USB会话不断线；单次切源4秒无新IDR会正常失败清理，不是会话总时长限制。
- 初始START排队时，原生渲染线程仍可能报告上一轮state2/reason0。仅为本请求owner及独立1.5秒待ACK留出时间，不把旧RESTORE当新撤销；激活后的真实撤销、错误归属、失联/清理隔离仍保留。

## 验证范围

根420 JVM/58套、构建/lint通过；同20项租约测试在冻结旧生产class复现reason0失败，新生产class全通过。冻结1.2.0真实ARM/Thumb执行也重现“新请求已排队、旧RESTORE尚未更新→渲染后新租约激活”，QNX API为替身。任务模型覆盖1000轮交接、停止顺序、异任务/异用户、未确认迁移与失败恢复；实际OEM DEX确认方法/字段、事件schema和成品中先归还后release的调用顺序。

**新原图标/跨屏生命周期/编码切源尚未实车验证。**这些离线证据不能证明地图所有版本都保留导航、实际图层混合或稳定30FPS；1.2.0的里程/主题/大中心窗实显也不因本版继承而冒称验收。旧Host/NCM/USB动态画面基线保留，不要求重复跑基础探针。本版不增加停车勾选、常规切模式拔线或累计限时；驾驶中不操作设置，不宣称道路安全认证。

参考：[Kiroha项目](https://github.com/Kiroha/byd-dashcast)提供了任务迁移的思路，但其AutoContainer/触控镜像和部分强停清理未移植；本版独立实现，保留我们的USB/NCM路径。[Android多屏活动启动规则](https://source.android.com/docs/core/display/multi_display/activity-launch)说明现有任务/启动方式会影响落屏，不把singleTask当成可随意复制的两份应用。
