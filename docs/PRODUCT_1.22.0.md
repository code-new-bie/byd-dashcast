# APK 1.22.0 / 仪表 1.22.0：投屏画面边缘淡入

应用 1.22.0 / code74，配套仪表 1.22.0（配对标记 RWVG）。**两者必须一起更新**：新 App 配旧仪表，或旧 App 配新仪表，开始投屏时都会因配对标记不符而拒绝，不会出现错位画面。

## 改了什么

以前投屏画面在窗口外沿 22–24px 内就被外框盖住，边界偏硬。现在改成参考图那样的淡入：

- **清晰区不变**：1.19.3 遮罩里完全透明的区域一个像素都没有缩小。
- **往外淡出**：从清晰区边界往外，画面按长尾 S 形曲线逐渐被外框色盖住。全屏左右 130px、上下 50px，小窗左右 200px、上下 50px。
- **淡出带里是清晰画面**：App 给仪表的画面比清晰区大出一整圈淡出带，像素密度不变，所以边缘是“清楚的画面变淡”，不是变模糊。

| 布局 | 以前 App 画布 | 现在 App 画布 | 在仪表上的位置 |
|---|---|---|---|
| 全屏 | 1696×456 | 1912×498 | (4, 89) 起，1:1 |
| 小窗 | 1280×720，由接收端缩到 768×432 | 1870×810，由 App 按 0.6 画到 1122×486 | (399, 101) 起，接收端窗口改为整屏 1:1 |
| 普通应用操作窗口 | 3392×912@320 / 2304×1296@480 | 3824×996@320 / 3366×1458@480 | 同上，一个 dp 对应仪表一个像素 |

**代价**：应用的画布变大后，贴着自己边缘摆的界面（比如导航的转向卡片、到达信息）会跟着外移，落进淡出带变淡；地图本身只是多显示了一圈。

## 设置变化

去掉了“其他接入的画面 → 画面比例（完整显示 / 填满区域）”。按视口尺寸排版的画面（定制地图的仪表界面、地图自带按钮、按屏幕名接入）一律铺满，淡出带也包括在内。以前默认的“完整显示”会把地图整体缩进窗口里的安全框、框外填模糊色，这种方式做不出淡入，所以取消。只有按车机主屏比例排版的旧式镜像，仍然完整缩进清晰区。

## 仪表侧改动

全部基于 1.19.3 的组件，按哈希固定：

- **KZB**：只换 `DXFullDark`、`DXCenterDark` 两张遮罩。新遮罩由 `analysis/fade_in_masks.py` 从 1.19.3 遮罩生成：Alpha 只降不升，清晰区保持为 0，所有半透明像素都落在 App 铺清晰画面的矩形以内。RGB 为 B2 直通乘数，即 Alpha>0 处为 255，清晰区为 0。
- **接收端**：START 标志 2（小窗）接受整屏窗口 (0, 0, 1920, 720)，不再只认 (576, 128, 768, 432)。共改 4 条 `moveq`，另把配对标记的比较值改为 RWVG。
- **HMI**：发布的配对标记 RWVF 改为 RWVG，只改 1 字节。
- 3dscreen.kzb、application.cfg、脚本、MCU、参考 OS 和版本文件都不变。

## 需要上车确认的一点

小窗以前按预乘方式合成，所以 1.19.3 给小窗遮罩配了“RGB 等于 Alpha”。现在小窗也改成和全屏一样的整屏 1:1 窗口，推断它会跟全屏一样按普通 Alpha 合成，所以小窗遮罩改用和全屏相同的直通乘数。这是推断，没有在车上读回。

如果上车后小窗边缘出现发白的亮边，说明小窗仍按预乘合成。修复方法是只把 DXCenterDark 的 RGB 改回等于 Alpha，其他都不用动。

## 验证范围

- App：单元测试 601 项、lint 0 错误。新增测试覆盖：视口形状的画面铺满整个画布、不被裁切；旧式镜像只放在清晰区内；小窗 START 为整屏窗口；配对标记为 RWVG。
- 仪表组件：从原件一次构建、按哈希核对。HMI 只差 1 字节，接收端只差 7 字节，KZB 只有两张遮罩变化（6 个资源后移，+12428 字节）。所有补丁位置都先核对原字节，改完再反汇编确认。
- 完整包：独立回读确认 app.sv 尾部的 MD5 和长度正确，53 个成员的顺序、属主和权限不变，只有这三个成员变化，os.sv、mcu.sv 和版本文件逐字节不变。
- 用成品 KZB 里的遮罩加新画布做了离线模拟，效果与确认过的方案图一致。
