# 0.10.0：综合修复与全屏实车合成首测

这次有实际全屏功能，不是只读检查或仅把背景变黑：将所选主屏/应用视频铺到1920×720的自有底层窗口，再联动五秒背景处理，让原生信息继续在上方。默认仍是已验证的小窗路线。APK code32，需要匹配仪表App；不是正式道路产品或持续全屏版本。

## 已承接与已实现

0.8.2主屏、指定应用独立副屏和正常退出的现场通过保持。0.9.1用户已确认两轮背景变黑、其他可见信息保留、约五秒恢复并可重复；不能继续把这个子功能写作完全未知。但它没有同时铺全屏视频，不能证明物理混合或全部告警。随后另一视频会话有画面，主动停止、未拔线，接收器STOP未确认，此异常独立处理，不推翻原Host/NCM基线。

| 任务 | 本次实际实现 | 验证边界 |
|---|---|---|
| 静默与STOP | DCS1独立idle/ADB读等待触发同线程保活；HELLO2不再用1.5秒无新视频帧截断健康静态会话，保留15秒心跳与31分钟总上限 | 新旧实际ARM对照；静默/心跳/STOP，丢心跳仍失败；不伪造H.264/FPS |
| 短探针 | 指定应用五秒探针交给前台Service；Activity隐藏不强断；必须确认所属EXIT/释放 | JVM完成/停止/缺退出反例；Android实机仍需回归 |
| 传输 | NCM空队列有界wait/notify；FIN超时从发FIN而非旧流量计算；错误含TCP状态 | 不据此宣布真实30FPS或解释所有现场故障 |
| 全屏 | 固定START模式1只接受0,0,1920,720,30；首帧ACK后一次背景START；五秒恢复后停视频 | 同流实际ARM/Thumb组合及小窗回归；物理合成待实车 |
| 层序/透明 | 自有全屏父窗口同步z=-3，窗口管理器也用-3；子局部z=1，小窗不变。HMI配置追加SurfaceBitsAlpha=8 | 不把视频抬到原生信息上，不降低全窗alpha，不改前景KZB/主题或硬件pipeline |
| 清理 | 停止/失败先恢复所属背景，再媒体STOP，最后TCP/USB；恢复失败也尝试STOP但不冒称全清理成功 | 缺确认仍隔离；不删guard、不自动切Host、不强杀共享服务 |

相对0.9.1仪表App只改变instrument-receiver和rc_hmi/application.cfg两成员。已实测HMI可执行文件/五秒桥、启动、参考2 OS、国内MCU、引导、USB角色及KZB逐字节保持。FULL携带相同OS/MCU等，不等于升级器一定跳过重写；按已有可恢复升级入口处理。

## 停车/台架操作

1. 保留旧包与回退入口、稳定供电。匹配0.10.0仪表FULL及APK，不混用旧App。按已有流程升级并正常重启，先确认原厂信息正常。
2. 同签名覆盖APK保留ADB身份，连接本机ADB，勾选匹配包/停车确认。沿用已验证NCM与USB授权；已有NCM不重复切，不额外要求U盘取日志。
3. 先原小窗短投屏/停止。若失败或清理隔离，停止本轮，不点全屏。
4. 选择车机主屏或指定应用，比例先FIT。点击“全屏实车合成…5秒自动恢复”，阅读专用弹窗再确认。
5. 预期背景区域出现实际所选视频，而非只有黑底；车速、挡位及当前可见信息保持在上方。首帧后最多约五秒恢复主题背景并退出视频；采集上限10秒，不能连点续期。
6. 重要信息消失、视频盖文字或未恢复时立即点停止，停止后续测试并按保留方式正常恢复/回退，禁止上路。HMI挂起时无法保证物理画面按时刷新。
7. 正常后重复一次，再测试中途停止/提前恢复；回归小窗、停止后拔线切Host/U盘。最后一键导出APK日志并反馈画面，不以ACK当混合或解码FPS证据。

## 离线证据与未完成项

私有349 Java/49套、31实际ARM/Thumb（含1000轮、同流全屏视频/背景激活/恢复/STOP）、真实30帧HD Java/DCV1/软件MD5、最终APK原厂框架接口及独立成品审计作为交付门槛。公开源码排除32项历史测试，公开测试数单记，CI不接车。

物理pipeline选路、EGL实际alpha、可见全屏混合、全部主题/动态告警、实车30FPS/长时和异常断电仍没有本版现场结果，不能写成验收完成。若仍黑底而前景在，继续针对物理合成定位，不重开已通过背景或基础Host切换。
