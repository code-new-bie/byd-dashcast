# 1.15.0 背景融合与应用内投屏接入

全屏和小窗改用本次确定的四边透明蒙版设计：视频在下，原厂实时背景按曲线透明渐隐，速度、挡位和告警等原生信息在上。只调整原有过渡带，不扩大显示区域，不把视频文字模糊或拉伸。保持原纹理尺寸和原深浅主题资源，不用静态示意背景替代仪表的实时背景。

按屏幕名接入修正了请求丢失：已有投屏时只是观察到外部应用画面，不再算“已经处理”；主线程条件变化或启动队列拒绝时，也不提前消耗请求；重新开启接收屏会重置旧请求标记。手动停止当前外部投屏后不会立即自动重开同一画面；内部应用仍有明确选择优先级，一次只运行一个仪表视频会话。新外部请求可等待当前投屏结束和清理完成后接入。主动恢复U盘模式会取消已经等待的外部请求，避免刚关闭连接又自动切回投屏。

打开“应用内投屏接入”，等待显示已开启，再点“复制屏幕名”。接收屏准备完成后复制按钮才可用。屏幕名为`fission_dashcast_meter`，在支持按名称选择屏幕的应用中填入。开关本身不切换仪表画面；关闭接入仍保留当前视频直到正常结束。普通应用投屏入口继续保留。

日志导出新增接入开关、真实就绪状态、显示ID、屏名、应用数量和是否正在借用接收屏的快照。不会记录窗口正文、地址或任务内容。用户提供的1793285320053日志实际标记1.14.1且只有六轮应用投屏，没有独立屏名接入事件；不能据此唯一断言那次现场失败由哪个条件触发。本版依据代码可复现的请求消耗错误修正，独立Android10模拟器覆盖接收屏、第三方客户端、复制就绪、重复开关、原地图入口和Surface持续显示。测试副本仅签名适配专用AVD，所有非签名APK负载与最终交付相同，不卸载或清数据；最终结果以配套交付审计为准，不等于车辆端已通过。

本次需要更新仪表App和配套APK，保留数据及ADB身份。原MCU、参考OS、Boot和视频协议保持；HMI启动/透明度修正及receiver原字节保持，仪表仅替换四张自有Alpha蒙版。全屏、小窗分别检查四边、深浅切换和停止恢复，再检查接收屏重复开关、普通投屏后外部接入及外部应用主动结束。

离线ARM/GLES、JVM和独立Android模拟器证据以发布时的实际结果为准，不视为真实QNX整机或实车已经验收。现有系统输入法及基础Host/NCM实车成果继续承接。
