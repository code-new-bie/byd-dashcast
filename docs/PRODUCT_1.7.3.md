# 1.7.3 应用入口准入与兼容能力

APK code46；仪表完整包与1.7.2逐字节相同，已安装该仪表App只覆盖APK，不清数据/ADB身份、不重刷MCU或OS。传输仍为原USB/NCM/AVC/DCV1，RWV4布局/里程/清理恢复保持。

## 根因与修复

本次两份实车日志明确APK1.7.2，四次都在APK预检失败、Service仍IDLE，未启动视频。一次复合的原车入口错误、三次单实例拒绝；没有实际应用版本/入口上下文，不能唯一断言现场是版本不符，也不能当仪表媒体失败。

原车导航原来只接受versionCode220102029，且把别名/独立任务条件一起报为版本未验证。现在按已安装的明确Meter入口、实际主入口、独立且非空affinity、公开可用/无额外权限/不reparent/受支持模式判断；不再将版本号本身当入口能力。已知主入口改名时回读系统正常launcher，选择Meter别名时仍与实际主入口比较，不能把Meter和自己比较。入口结构符合不代表每个导航版本业务同步都已实车认证。

通用应用原先扫描包内所有Activity一票否决。新规则仅检查所选任务域：首个真实入口/同root/同affinity链；不同任务域的无关Settings单任务不再否决标准入口。相同任务域仍有单任务转发/允许reparent、或所选入口本身是singleTask/singleInstance时继续拒绝，避免复用和搬移原主屏任务。没有为“全应用可投”删掉真实保护。

```text
实际安装入口 → 能力/任务域检查 → 正常USB与恢复准备 → 自有副屏任务 → 既有视频链
                  └ 不满足：显示原因并记录事实；不启动、不搬主屏、不回退主屏镜像
```

## 使用和诊断

覆盖安装APK后，打开“应用中心”，必要时点“刷新应用能力”。具备条件的应用才显示选择/允许开始；不具备条件的显示“原因”，不会诱导反复开始。具备条件仅指入口检查通过，不冒充目标机画面成功。已有保存但已不兼容的选择会显示原因而不是偷偷改选应用。

开始前和shell内均重新检查入口；导出包含实际包/版本、候选/真实root、模式/affinity/permission及具体失败条件。即使尚未开始视频，也会导出最多32个应用的有界能力快照；点击“原因”的当前应用另外记入协调日志，不受32个列表截断影响。日志不收集Intent数据、账号或APK内容。

这不是万能应用虚拟化：真正只有同用户单任务入口且没有已适配独立副屏入口的应用仍不支持。不能简单添加NEW_TASK/MULTIPLE_TASK承诺复制任意singleTask界面；Android10源码仍会寻找既有singleTask任务。[AOSP实现](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-10.0.0_r47/services/core/java/com/android/server/wm/ActivityStarter.java)。不创建其他用户/数据空间、不修改原应用、不强停/删除原任务。

## 回归与证据边界

新增版本变化/选择Meter入口/无关task域反例，原singleTask/同域转发/权限/错误affinity保护仍需通过。实际冻结1.7.2与新编译resolver在相同PackageManager替身上执行10例，各3项旧误拒绝在新实现通过、其余保护保持。它不是目标Android PackageManager或真实应用已运行的证据。

维护者另核全量单测、独立源码构建及生产DEX、原签名/两文件保存负载；本页不以旧CI冒作本版状态。仪表全部6个release、53个App成员/元数据含原MCU/参考OS完全相同。所有原车业务/未知应用和目标机实显仍需现场结果，不能把代码修复描述为已实车根治所有应用。
