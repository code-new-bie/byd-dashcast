# 1.1.0 原生导航布局

布局方向：顶部挡位/时间/原车状态，中间大地图，下方功率、车速、电量、续航和里程。是基于当前仪表资源的结构优化，不是一比一复制参考照片的字体、地图配色或全部主题。地图内容仍由所选导航应用负责。

## 使用

1. 使用配套 1.1.0 仪表 FULL 和同签名 APK 覆盖更新。FULL 含 os.sv、app.sv、mcu.sv 及三项版本文件；与冻结 1.0.1 比只有 app.sv 变化。已有参考 OS 的功能改动只在 App，但完整升级器可能重刷未变组件，按已有可恢复升级入口操作，不能称零风险。
2. 仪表正常重启，先确认原生画面正常；APK“设置”开启“导航仪表布局”，选择高德等已成功的导航组件，再点“开始”。正常模式切换不增加拔线/停车勾选；应用/设置操作不要分心驾驶。
3. 首帧视频之后进入紧凑布局，原生顶/底深色衬底提高文字对比，原仪表装饰性双表盘淡出，数字与单位保持原厂绑定。电量/续航、告警和指示灯仍由仪表处理。地图上下部分会被状态/数据栏覆盖，不承诺任何应用都重新排版为该中央区域。
4. “停止”恢复原背景和布局；切 U 盘沿用先停投/确认清理→释放接口→单次角色请求，无时长限制、不靠周期重连。失联五秒租约到期也恢复。关闭布局开关后下次开始走原兼容小窗，而非“全屏但旧双表盘”的另一独立选项。
5. 若原生数据异常、文字越界或有遮挡，立即停止。需要时用原 1.0.1 同签名 APK/配套 App 回退；不盲删 guard、杀共享服务或强切 Host。导出日志仍在诊断页下载目录，不新增仪表 U 盘取日志要求。

## 改动范围

- Kotlin 产品会话准备检查 HMI word29=NAV0，激活检查 NAV1，恢复同时确认 NAV0。旧 1.0.1 没有布局能力则开始前拒绝，不把旧 ACK 说成新布局成功。NAV 表示原生属性设置及自有节点就绪，不等于物理屏幕/告警验收。
- 新 Thumb 扩展在原渲染线程切换私有继承 int `Dashcast.NavigationLayout`，仅在值/RootPage 变化时设置；原 nonce/PID/epoch、五秒租约、15 秒视频心跳保持。缺少自有衬底节点时撤回布局并拒绝报告就绪。
- KZB 保持所有原 ID，追加属性和四个状态管理器。只给 Gear/Cluster/Top_Bottom 三个父组接新管理器，并在原 Content 中插入两个自有、默认不可见的对比衬底；不替换子节点原厂状态管理器。状态 0 没有覆盖值，恢复当前原厂状态而非旧截图值。
- 3105 个原资源逐字节保持，原告警/指示灯/数值绑定资源不改；独立审计撤销两新节点及三父组头即可字节级重得原 StartupPrefab。app.sv 53 成员只有 HMI/KZB 两项变化，接收器/USB 脚本/媒体库及参考 OS、MCU、Boot 不改。

## 证据边界

376 私有 JVM/53 套、24 实际 Thumb/资源回归及本次 30 帧 H.264/Java/原 ARM parser/STOP0 通过；原生系统 API、媒体与 Screen 是替身。新布局有成品，不是纯日志检查包，但尚未实车验收位置/全部动态告警，不宣称道路安全或所有主题通过。1.0.1 的共显/正常停止/本次 Host 用户成功继续保留；真实 FPS/PTS、首轮源更新与日志头标签问题没有借本次布局升级宣称修复。

原生组件复现见 [BUILD](BUILD.md)，版本边界见 [VALIDATION](VALIDATION.md)。1.0/1.0.1 历史文档和构建器保留，只代表写作时状态。
