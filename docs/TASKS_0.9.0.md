# 0.9.0：F1只读显示检查

本版完成全屏计划中的只读取证子任务，不是全屏版本。原生HMI背景/透明度/层级均不改；受控HMI接入、实际EGL/硬件混合及背景恢复仍未闭环，不得行驶使用。

## 已实现

- 固定DCV1 type9/20字节请求，受限整数选择显示/窗口/流及0～3页，无任意路径/shell/显示参数。
- F1P1响应元数据40字节＋每页最多4096字节，校验版本、回显、长度、枚举、保留位和分页；不改变旧FRAME ACK。
- 最多32资源/128请求/128KiB文本/10秒采样预算。单页文件IPC共享500ms，关闭另有500ms；网络读仍沿用已有15秒上限，不能把采样预算当严格总墙钟时限。
- 同一有序TCP流：单独检查不建视频；测试图每帧ACK后最多采一页。普通主屏/持续副屏默认不查。
- 失败、缺失、权限不足、截断和未完成明确记录，绝不输出“全屏通过”；不抓取仪表像素或敏感车辆信息。
- 旧小窗参数、六处高清输入、USB/角色脚本、HMI/参考OS/MCU保持；视频无激活，正常ADB/USB许可保留。

## 停稳测试

1. 正常升级匹配仪表App/重启、同签名覆盖APK，保留可恢复手段。FULL仍可能重刷其携带的未改组件。
2. 只在没有目标NCM时沿用拔线切NCM流程，再接线/授权；已有NCM不反复切换。
3. 点“F1. 只读仪表显示检查”，预期不改变仪表界面或模式。
4. 点“F1. 小窗测试图＋显示检查”，确认10秒动态小窗及正常退出。
5. 再只读检查一次；保持当前APK实例，一键导出到下载目录。不要把原始车端日志直接公开到Issue。
6. 再按普通投屏/副屏、停止、重复及清理后拔线Host分场景回归。异常先停止，不删guard/连发命令。

F1读不到属性不等于不存在窗口；窗口VISIBLE/ACK也不等于实际合成正确。实际alpha位数、原生信息可读性、告警优先级、全状态/异常/长时和稳定30FPS仍需对应验证。

## 复现与证据边界

APK可按BUILD构建。另提供纯F1接收器覆盖工具（需自行提供匹配原件），固定输入哈希/四个允许范围，保留原live mask入口检查/返回。它不是QNX HMI SDK，不是固件包装器，也不启用全屏。

私有321 JVM/46套、11 ARM及最终30帧高清契约/独立成品审计通过，QNX/媒体/USB均有替身。0.8.2动态画面/独立副屏/正常退出用户短测已通过；0.9.0目标机运行尚未验证。公开副本独立测试/CI不替代实车或道路安全。
