# 仪表1.19.3：小窗白边修复

1.19.2实车照片显示，全屏的浅色暗圈已经消失，但小窗边缘出现约24px宽的白边。白边比外框和地图都亮，从透明度刚大于0的位置起就饱和，所以内容看起来像被硬切；挨着深色卡片的地方稍暗。

## 原因

两种布局最终合成时用的透明度约定不同：全屏按普通Alpha合成，小窗按预乘Alpha合成。1.19.0全屏有暗圈、小窗没有，1.19.2全屏平滑、小窗出现亮边，这两组照片都符合这个判断。B2让两张遮罩都输出普通Alpha的(C, a)，小窗按预乘方式叠加后就成了C + V(1−a)，边缘超过两侧亮度，形成白边。

小窗为什么走另一条合成路径，目前只是推断（最可能是缩放后的小窗视频由Screen的GPU合成，并遵守了窗口的预乘声明），没有在车上读回窗口或管线信息。

## 修改

B2的模式5把帧缓冲乘以遮罩纹理的RGB，所以每张遮罩的RGB决定了它输出哪种约定。只把小窗遮罩DXCenterDark的RGB改为等于Alpha：小窗帧缓冲回到(C·a, a)，和1.19.0完全一致。全屏遮罩DXFullDark和HMI保持1.19.2不变。

以1.19.2配对组件为底，KZB的3123个资源中只有DXCenterDark的内容变化，后面两个资源随之后移，文件增加292字节。新PNG的Alpha与1.19.2小窗遮罩逐点相同，RGB逐点等于Alpha，只含IHDR/IDAT/IEND。完整包中只有app.sv的bic_byd_stha.kzb变化，原MCU、参考OS、Boot和版本文件保持。

不要把这张图当作普通图片再做预乘或重新保存，也不要和其他版本的HMI或KZB混用。复现方法见[构建](BUILD.md)。

## 验证范围

组件重建与交付的KZB逐字节一致；完整包回读确认只有这一个资源变化。用实际Alpha离线模拟，修正后地图行和卡片行的边缘亮度都单调过渡。没有在本版实车上验证。如果小窗出现暗圈，说明小窗并非预乘合成，需要读回窗口和管线信息；如果全屏有任何变化，说明构建有误。
