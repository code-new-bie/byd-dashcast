# 1.4.0：有效内容区、原厂配色与四边融合

本版需要匹配APK与仪表App，两端能力指纹RWV3。不是只升级APK；1.3.0/1.2.0仪表不能满足本版布局契约，旧版本APK也会拒绝新的产品合成能力。原同任务交接、原应用图标、停止归还导航任务、USB/NCM/AVC链保留。

## 问题与修复

1. 旧融合依赖新材质/嵌套主题赋刷，叶节点缺初始画刷，激活仅查父透明度；资源存在不代表真的画出。改为200个明确原厂ColorBrush叶，原state2直接切换其深浅画刷，不新建材质或GL全局坐标shader。激活核对全屏/中心两个直接绘制容器互斥状态。该状态回读仍不是现场像素认证。
2. 原先按1920×720或768×432外框排完整应用，再覆盖边缘，会损失提示。现在副屏按有效内框创建，内容映射进内框，边缘像素只作为过渡余量。不是裁掉整套UI的四边。
3. 总里程父留位改为(1393,648)/0.70，原415×60组的模型下界为690而非旧703.2，增加底边余量，完整保留里程模式、单位和数据绑定；地图上/下内容避开原生状态及底部数据。最终父子排版和可读性仍需目标仪表确认。
4. 中心窗扩大保持，但四边也有原生软化；不再宣称外框16:9就等于内容16:9。

| 几何 | 全屏 | 大中心窗 |
|---|---|---|
| 物理窗口外框 | 1920×720 | (576,128)，768×432 |
| 实际内容内框 | (96,128)，1728×432，4:1 | (600,152)，720×384，15:8 |
| 自有副屏逻辑尺寸 | 1920×480 | 1200×640 |
| 不变AVC传输 | 1920×720 | 1920×720 |
| 编码画布中的内容 | (96,128)，1728×432 | (60,40)，1800×640 |

中心窗由QNX的x0.4/y0.6映射逆转编码重采样，不把编码内框1800×640当成最终内容比例。四边渐变与原生保护区不计入可读面积。地图自己的昼夜由导航应用控制；仪表融合色跟随原厂主题，APK浅色开关仅改APK。

## 使用

1. 同签名覆盖APK，升级本版仪表App后正常重启。FULL携带未改的原MCU、参考OS和引导，升级器仍可能重写；不要混用旧组件，保留原有回退包。原厂信息异常先恢复，不继续投屏。
2. 产品设置开启导航布局是全屏，关闭为大中心窗；先停止再更换。建议关闭“中心裁剪”，保留全部应用提示。ADB/USB正常许可继续使用原身份，不需清数据。
3. 正常连接并开始导航，检查上方挡位/时间、下方功率/车速/续航及右下里程。四边不能吞掉内框内的转向提示。
4. 投屏中从原地图图标打开，主屏可操作同一任务；主屏尺寸不变，仪表按完整适配共显时可能留边。切其它应用后任务回自有副屏，按内框比例排版。不是复制两份独立导航。
5. 切换原厂深浅主题观察边缘；地图昼夜独立。正常停止后原背景/布局恢复，再重复一次；正常Host/NCM切换仍不要求手动拔线。

原车模可能关联车门/安全带/ADAS等业务，真实警告仍优先显示，不为美观隐藏这些分支。没有自动车速判断、停车勾选或人为两小时限制。不要在驾驶中操作设置。
