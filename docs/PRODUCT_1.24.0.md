# APK 1.24.0：上次投屏没结束干净时自动清理

应用 1.24.0 / code79，配套仪表仍是 1.22.0，不用重刷仪表。签名不变，覆盖安装即可。

## 以前的问题

投屏结束时，如果有一步收尾工作 App 没能确认做完，App 会锁住，提示“上次投屏尚未完全结束，已停止重试。请重启仪表和应用后再试”。之后开始投屏、切换仪表模式都用不了，只能手动重启。

车上导出的日志里一共锁定过 3 次，都是“投屏程序没确认退出”，USB 每次都已正常释放。其中 2 次投屏程序其实已经退出了，只是退出时报了错。

## 现在的做法

发现锁定后，App 马上在后台自动清理，不用你操作：

1. **只差投屏程序没确认退出（日志里的 3 次都是这种）**
   - App 通过车机调试连接找到上一次的投屏程序和它拉起的子进程，强制结束，并确认它们确实没了。
   - 只认我们自己的投屏程序：不碰被投屏的应用，不碰“应用内投屏接入”的接收屏程序，也不碰其他用户的进程。
   - 程序结束后，它占用的截屏显示和虚拟屏幕由系统自动收回。
   - 如果仪表那边当时也确认结束了，就直接恢复成“可以开始投屏”；如果仪表那边没确认，下次开始前会先确认仪表已经空闲（沿用 1.7.2 起就有的检查）。
   - 通常不到 1 秒就清理完。
2. **车机这边 USB 或 App 自身没确认释放（日志里还没出现过）**
   - 这部分只能靠重启 App 释放。App 会自动重启自己，大约 5 秒后重新打开（如果当时界面在前台）。
   - 重启后，下次开始投屏前会先确认仪表已经空闲。
   - 2 分钟内不会自动重启第二次，避免反复重启。
3. **清理没成功时**
   - 页面显示“上次投屏没能自动清理”，主按钮变成“重启应用”，点一下 App 就重启。
   - 只有重启 App 后还是不行，才需要重启仪表。

清理期间页面显示“正在清理上次投屏”。这时点“开始投屏”，会在清理完成后自动开始。

## 验证范围

- 单元测试 622 项、lint 0 错误。新增测试覆盖：进程列表解析、只挑中我们自己的投屏程序和它的子进程、结束后确认消失、结束不了时算失败；锁定原因的区分和清理后的状态转换；页面在清理中、排队开始、清理失败时的显示；自动重启的间隔限制。
- Android 10 模拟器（在 App 自己的进程里制造锁定）：
  - 模拟器没有硬件视频编码器，真正的投屏程序起不来，所以用一个替身程序：进程名和参数与真的一样，也建同名的截屏显示，并拉起一个 logcat 子进程。
  - 只差投屏程序的锁定：App 找到替身程序和子进程，结束并确认，用时约 0.4 秒；截屏显示从 2 条变为 0 条；状态恢复为可以开始；提示“已清理上次投屏，可以重新开始”。
  - 调试连接连不上时：显示“没能自动清理”，没有误报成功。
  - USB 没确认的锁定：App 自己结束进程，约 5 秒后重新启动，并由调试连接重新打开页面；页面提示“仪表正在恢复，稍候点击‘重新连接’即可继续”。
  - 2 分钟内第二次：没有自动重启，页面显示“重启应用”按钮；点按钮后 App 重启并重新打开页面。
- 模拟器上调试服务只走模拟器内部通道，不监听 TCP 5555，测试时用端口反向转发接到模拟器的调试端口；车机上调试服务本来就监听 TCP 5555。
- 没有在模拟器上验证的：真实投屏程序被结束后，被投屏的应用是否回到车机主屏（按安卓 10 的默认行为应该会）；清理期间排队的开始（需要仪表）；界面不在前台时的自动重启。

以上都还没有在本版实车上验证。
