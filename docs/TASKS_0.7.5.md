# 0.7.5 高清传输节奏与剩余门禁

## 本版完成

- 保留0.7.4的1920×720实际输出尺寸门控、PTS FPS/墙钟FPS证据和固定DCV1时间轴。
- 新增`FramePacer`，在每个同步DCV1 `FRAME` 写入前按单调时钟排程`33,333,333 ns`，避免编码器/管道批量释放造成传输突发。
- 慢ACK不通过重复帧或补发追赶，记录`FRAME_PACER`的迟到帧数、最大迟到和实际传输间隔。
- 仪表 OS、MCU、启动镜像、USB角色脚本、NCM和接收器协议不改；APK升为0.7.5/code22，必须与匹配接收端成对使用。

## 离线门禁

必须通过Android单元测试、assemble、lint、真实Baseline H.264/Java DCV1/高清ARM解析、成品包装和独立审计。单元测试只证明节奏器不会突发排程或用额外帧追赶慢ACK，不证明设备端实际帧率。

## 现场门禁

1. 停稳或可恢复台架刷入匹配的0.7.5 APK和仪表App。
2. 短时确认`SHELL_CAPTURE_FORMAT`为1920×720，`SHELL_CAPTURE_COMPLETE`接近30 FPS。
3. 确认`FRAME_RATE_GATE`输出节奏和`FRAME_PACER`传输起始FPS/平均间隔；持续迟到时先检查USB/NCM吞吐和仪表ACK。
4. 观察仪表动态画面并独立测量显示FPS；不能用ACK或车机日志替代。
5. 短测通过后再做重复投屏、停止清理、视频后Host、600秒、1800秒和异常回归。

动态告警隔离仍未完成，只允许停车或可恢复台架验证。
