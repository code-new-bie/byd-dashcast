## 应用接入开关

“应用”或“设置”中的“应用内投屏接入”只准备车机接收屏，不切仪表模式、不启动视频、不改变仪表。开启后复制`fission_dashcast_meter`，在自身支持外部屏幕的应用中发送；实际收到可见窗口后才开始视频。

Dashcast应用列表中的开始功能仍可直接使用，不需要开启接入。内外入口共用唯一视频会话，手动投屏优先；更换应用先结束旧会话。停止视频回到待命，旧窗口不会自动反复重启，发送方结束并重新发送可开始下一次。

关闭接入不打断正在显示的画面。外部应用仍占用窗口时，为避免其任务迁回主屏，实际释放延迟到视频结束且发送方退出外部窗口；期间不接受新的自动接入。关闭接入和停止投屏是不同操作。

定制地图原按钮可见时继续使用原按钮。原按钮缺席时，接入开启且启用Dashcast无障碍服务后，主屏定制地图显示备用“仪表投屏”入口，离开地图即隐藏，不重复覆盖原按钮。它是Dashcast提供的入口，不修改地图APK或车辆能力信号；原厂独立MeterActivity及meterDisplay名称兼容保持。

## 根因与修改

| 问题 | 根因及处理 |
|---|---|
| 几秒后自动退屏 | 原背景恢复后旧skip计数为0，APK却仍要求增长。改为两端RWVF实际2D遍历及根背景绘制反馈。 |
| 停止后清理隔离 | 资源关闭标记不保证框架线程退出。清理完成后正式结束采集进程，仍要求真实shell-v2 EXIT，未知清理不放行。 |
| 定制地图短暂停顿导致PTS断档 | 归属与可采集性分开，任务查询移出GL循环；仅保留最后合法帧按真实提交时钟输出，不改编码PTS、不放宽2秒合同。 |
| 停止后丢失命名接收屏 | 待命屏和单次视频生命周期混在一起。独立前台服务拥有接收屏，视频只借用其输出Surface。 |
| 主屏操作比例不自然 | 曾把仪表承载比例用作普通应用比例。业务界面改用主屏实际尺寸，仪表独立完整显示/裁剪；原生地图宽源保持。 |
| 车模及普通道路残留 | 运行时实例被原加载器改名为NN编号，仅匹配预制体原名会漏掉；资源属性也会被更新器覆盖。现在识别NN95/NN96/NN97并核对当前注册指针，在真实2D绘制及3D网格分发入口过滤，停止后恢复原调用。 |

过滤限定叶名、直接父级、有限祖先和当前实例身份。3D普通路面节点必须直接位于RoadRoot下，目标车辆内部即使有同名Plane也保留。其他场景同名对象、目标车辆、雷达、文字告警和车门场景保留。全屏小窗共用活跃租约；原背景、曲线、窄边、主题和信息布局资源逐字节承接1.12.6。

普通地图使用独立的`fission_dashcast_native`别名，保留地图SDK按`fission_`前缀寻找仪表的合同；待命接入独占可复制的精确名称，两者可先后创建，切换开关不会重建正在投屏的地图显示屏。普通应用操作区按真实主屏客户区调整，系统栏/输入法区域变化不再强制使用仪表比例。

原RX洞已满，新增独立RX LOAD并迁移程序头表，保留原LOAD地址/权限、解释器、unwind及RELRO。`tools/build_product_runtime_components.py`只接受精确原件并输出组件，不是可刷FULL。
