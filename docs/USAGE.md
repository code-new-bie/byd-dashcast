# 停稳验证顺序

当前0.9.0 F1请优先按[专项目录与步骤](TASKS_0.9.0.md)：匹配两端后，先只读检查，再10秒小窗测试图/检查，最后再只读并直接导出。已有NCM不重切，F1按钮不切模式/不改图层；全屏未启用。下面0.8.2是原投屏验证流程的历史说明，不能用旧仪表App替代F1接收端。

前提：匹配仪表App与已安装的参考包2 OS、可恢复升级流程、稳定供电、车机Android10及正常本机ADB。不要把本仓库当作已刷固件或车型兼容声明。

当前开发APK0.8.2必须匹配0.8.2高清接入修复仪表App，需要同时更新两端。已有参考2 OS者本轮功能只需App；FULL仍携带原OS/MCU/引导，升级器可能重写，按现有可恢复入口处理。正常重启后先测试图10秒及二次播放，再主屏10秒，最后指定应用探针/投屏。收到视频失败不代表清理失败：完整EXIT、资源释放与接收器/USB清理均确认后，仍会如实报告失败但允许再次操作；任何清理未确认仍停止测试。

1. 保持车辆停稳/在可恢复台架。通过已验证的升级入口处理匹配包，独立release目录，不与旧包混放；按所用App-only/FULL包核对实际刷写范围。升级后正常重启清除旧RAM锁，检查原仪表信息正常。
2. 安装匹配签名APK；同签名才可覆盖保留数据/ADB身份。新构建签名不匹配时停止，不为覆盖安装盲目卸载清数据。
3. 打开APK，连接/授权本机ADB，确认uid2000；退出原厂导航，勾选匹配仪表包/车辆停稳确认。
4. 移除仪表U盘和数据线，单次请求NCM；观察仪表提示。拔线时车机无设备是正常前提，不能判成切换失败。
5. 接已验证的车机↔仪表USB数据线，核对唯一目标NCM，授权系统USB访问。已有目标NCM再点NCM应保留连接、不重新发送命令。
6. 做5秒动态画面验证，观察仪表真实画面且不遮挡重要仪表信息；结束后确认窗口退出。可在同一NCM连线内连续三次，不重启/拔线/切模式来掩盖重复使用问题。
7. 清理成功、窗口已退后拔线，请求Host，再用无升级文件普通U盘验证真实Host。基础模式循环和视频后Host恢复分别记录。

切换失败、窗口未退、STOP未确认或重要信息被遮挡：停止本轮，必要时正常重启走既有恢复方式。不要连发命令、手动删guard或强制切Host。

## 0.8.2远程副屏验证

1. 更新0.8.2仪表App和同签名APK；不能只装新APK继续用0.8.1或更早高清接收器。
2. 不切NCM、不连接仪表，在“远程副屏目标”刷新应用列表，选择一个普通可启动应用，点击“1b. 远程副屏探针”。
3. 只有同时出现`SHELL_CAPTURE_REMOTE_CONTEXT`、`SHELL_CAPTURE_REMOTE_DISPLAY_CREATED`、`SHELL_CAPTURE_REMOTE_AM exit=0`、实际1920×720格式、SPS/PPS/IDR、`SHELL_CAPTURE_COMPLETE`和`REMOTE_DISPLAY_RUNTIME_PASS`才算车机远程副屏门控通过。
4. 车机门控通过后，再按本页原有NCM、USB授权和停稳投屏顺序验证仪表；持续投屏时可选择同一应用。应用跨屏、secure surface、固定主屏或多窗口兼容性必须按具体应用分别记录。

远程副屏探针通过不代表QNX仪表显示通过；仍需人工观察画面、安全信息无遮挡、停止清理和视频后拔线Host恢复。

## 0.5.0持续小窗验收

先完成短时检查，再设置持续时长600秒，点“开始持续投屏”，保持停稳并确认可见动态画面及不遮挡。打开导航，确认投屏不中断；可回应用或从通知栏停止。状态只有在采集EXIT、接收端STOP及USB退出都确认后才结束；ACK/visible属性不是人工画面证明。

10分钟通过后再做1800秒；连续启动/停止三次、界面重建后查看状态/停止、结束后拔线恢复Host并用普通U盘验证。无视频Host/NCM循环和重复NCM按钮单独回归。持续模式不保存视频文件；时长1～1800秒不是10秒片段循环重连。

USB断开只中止当前会话，不自动换模式或重连。出现QUARANTINED/清理未确认应停止测试，确认正常恢复后重启仪表和APK进程，不为重试删锁或强杀共享服务。此版本未做道路使用或安全层级验收。

## 历史0.7.9 G3与高清首测（0.8.1改为FPS诊断，不因偏差停止视频）

在短时链路已通过且车辆停稳/台架可恢复的前提下，先确认 APK 界面为0.7.9、仪表App为匹配高清版本。先点击G3探针，观察`SHELL_CAPTURE_CODEC`、`SHELL_CAPTURE_FORMAT`实际1920×720、滚动/最终`SHELL_CAPTURE_FPS_GATE status=PASS`、`SHELL_CAPTURE_COMPLETE`和APK最终的`G3_RUNTIME_HARDWARE_AVC_PASS`；再做投屏，观察`FRAME_RATE_GATE`输入/输出/丢帧、`FRAME_PACER`的传输起始FPS/平均间隔/迟到帧、`min_transport_interval_us`、`max_transport_interval_us`、`burst_intervals=0`、`output_interval_us=33333`和Surface重复cadence配置；如出现迟到，确认迟到后的相邻发送间隔没有追赶突发。真实仪表画面、QNX解码和30 FPS仍以现场测量为准。出现告警遮挡、黑屏、残影或清理未确认立即停止。短时通过后再做600秒、1800秒、后台、自然结束、异常退出和视频后Host回归。

## 0.6.0比例与地图区域

中央640×240窗口没有完成动态告警隔离；固件存在中央WarnText节点，不称其安全区。**仅停稳/可恢复台架测试，不进行道路测试。**模式只影响持续投屏，旧5秒诊断/测试图保持原显示对照。

1. 同签名覆盖APK，保留ADB身份；仪表已经是0.5.0则不重刷。沿用已通过的授权/唯一NCM连接，不为每次比对反复切模式。
2. 在“持续投屏画面比例”选择完整画面保持比例fit（默认）、中心裁剪crop、自定义地图区域region或原拉伸stretch。region输入左/上/右/下百分比，0～100、右大于左/下大于上，每边跨度至少5%；这是手动区域，不是自动识别地图。
3. 本轮勾选台架/停稳且无关键告警的确认，先用20～30秒对照。fit完整源、可能留边；crop填满但舍弃上下/两侧；region保留指定地图区域。确认弹窗显示冻结选项，开始后切其他应用可看到该区域内容，不能在运行中改变选项。
4. 停止并确认窗口退出/STOPPED后再改模式重测；比较实际比例、边缘是否裁错/旧画面残留、文字清晰度，以及仪表关键信息。发现遮挡、告警、画面异常或清理未确认立即停止，不靠确认勾选宣称安全。
5. 导出日志中检查CAPTURE_SELECTION、PROJECTION_CONFIG、SHELL_CAPTURE_GEOMETRY及退出记录；实际主屏尺寸用于换算百分比，不硬编码所有车均1920×1080。新几何通过后再补600/1800秒自然结束、后台、再用及视频后拔线Host回归。

原0.5.0已现场通过两轮动态画面/后台/停止及Host/U盘；新增几何需要单独实显验收，不把已通过项重新列为待开发，也不把桌面黑边模拟当OEM SurfaceFlinger已验证。

## 日志

使用APK“一键导出日志到下载目录”。ZIP只有有界APK/USB/OEM/Android状态，不是仪表日志。0.5.0持续会话历史属于进程，不随Activity重建丢失；运行中也可导出。旧短探针/模式主report仍属于Activity，若要完整记录这些操作，测试后保持当前界面直接导出。

日志可能含网络地址/设备路径/密钥指纹，发公开Issue前先人工脱敏。不要把签名私钥、ADB私钥、原厂/参考固件或全量系统日志放进源码/Issue；可刷包分发单独审核来源和测试范围。不要求仪表U盘日志回收。
