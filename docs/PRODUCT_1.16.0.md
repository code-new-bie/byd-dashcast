# 1.16.0 背景与应用接入修复

请配套更新同一交付目录的APK和仪表App，覆盖安装并保留数据。完整仪表包的原MCU、参考OS和Boot保持不变。

全屏和小窗使用此次重新制作的背景：四边形状、渐隐和1920×720透明度按原图保留，活动时底色分别为深色`#191c26`和浅色`#cddbe5`。仪表主题决定背景深浅，地图自己的昼夜主题仍由地图设置决定。停止后恢复原厂界面。车速、功率、里程、挡位和告警仍在上层。

小窗清晰视频覆盖整个原物理窗口（768×432），不再只在中央720×384清晰、外围用模糊补边。以真实物理窗口比例做等比映射，车机操作界面仍用原主屏的业务尺寸；全屏窗口和传输1920×720保持。选择“完整显示”与“铺满区域”的裁边取舍仍保留。

此前屏幕接入和定制地图把任何`fission_`屏或系统叠加屏都当成冲突，从创建接收屏之前就退出。本版仅阻止真正相同的自有接收屏名称，不关闭、移动或接管其他显示屏；公开屏名仍为`fission_dashcast_meter`。

开启“应用接入”，等待复制按钮可用，再在发送应用中使用该名称。仍为一次一个视频；正常应用投屏和按名称接入继续共用受控切换。开关本身不切仪表画面。未完成宿主绑定的启动会自动关闭，已绑定的接收屏与视频没有新增时长限制。

重点观察：存在其他显示屏时开启接入和定制高德投屏；普通高德切到其他应用再通过原图标返回；全屏/小窗的深浅切换、四边和停止恢复。真正相同名称被其他服务占用时会保留原屏并提示冲突，不根据名字删除其他服务。

新背景用两个完整尺寸的共用透明度纹理及两个极小底色纹理还原，四个纹理槽保持。解码RGBA占用约10.55 MiB，比此前约5.27 MiB增加约5.27 MiB，避免把四张图都放大到完整尺寸。可执行程序、视频协议、接收器和3D场景保持原字节。

仓库内的[四张背景原图](../assets/backgrounds/)由项目所有者制作；组件构建命令见[构建说明](BUILD.md)。模拟器、指令回放和离线图形结果不等于本版实车验收，完整目标QNX/Kanzi仍需车辆反馈。
