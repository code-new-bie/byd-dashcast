# 0.7.6 高清传输迟到重锚定与剩余门禁

## 本版完成

- 保留0.7.5的1920×720实际输出尺寸门控、PTS选帧、固定时间轴、Surface静态 cadence和`FramePacer`发送排程。
- 修正慢ACK/编码路径超过一个帧周期后的排程：迟到后下一 slot 从当前实际发送起点重新等待`33,333,333 ns`，不沿用旧 deadline 追赶。
- 增加回归测试，确保慢路径之后不会连续突发发送；不复制图片、不补发错过的帧。
- APK升为0.7.6/code23。仪表 OS、MCU、启动镜像、USB角色脚本、NCM和接收器协议不改；仪表配套包沿用0.7.5已审计接收端二进制，仅重新封装为可追溯的匹配包。

## 离线门禁

必须通过Android单元测试、assemble、lint、真实Baseline H.264/Java DCV1/高清ARM解析、成品包装和独立审计。`FramePacer`测试只证明慢路径不追赶突发，不证明设备端实际显示帧率。

## 现场门禁

1. 停稳或可恢复台架刷入匹配的0.7.6 APK和仪表包。
2. 短时确认`SHELL_CAPTURE_FORMAT`为1920×720，`SHELL_CAPTURE_COMPLETE`接近30 FPS。
3. 确认`FRAME_RATE_GATE`输出节奏和`FRAME_PACER`传输起始FPS/平均间隔/迟到帧；若有迟到，确认后续发送没有追赶突发。
4. 观察仪表动态画面并独立测量显示FPS；不能用ACK或车机日志替代。
5. 短测通过后再做重复投屏、停止清理、视频后Host、600秒、1800秒和异常回归。
