# Dashcast

BYD Android 车机 → QNX 仪表 USB 投屏工程。当前开发源码 **0.8.2 高清接入修复版**，需匹配 **0.8.2仪表App**。在0.8.1基础上修正解码入口仍使用小窗尺寸的问题、框架文字污染视频stdout，以及视频消费者失败后立即断开ADB的问题。视频与解码输入均为1920×720，仪表仍显示原640×240小窗。原NCM/DCV1和模式切换路线保持；恢复实显、应用跨屏与实际30FPS待现场验证，公开Release仍为0.4.4。

此项目用于可恢复台架或车辆停稳时的验证，不是官方固件、通用车型适配包或行驶中使用的生产产品。仪表 MCU 不修改，视频不使用激活码/token/设备绑定；正常 ADB 和 USB 访问授权仍然必需。

## 当前成果

- [0.8.2修复与现场验证](docs/TASKS_0.8.2.md)：需同时更新APK和仪表App，先验证测试图、主屏，再验证指定应用。

- APK 经已授权的本机 ADB 和原厂导航文字中继，请求仪表 Host/NCM 模式。
- 车机画面经 shell SurfaceControl 镜像、硬件 H.264 Baseline 编码，通过用户态 USB NCM/TCP/DCV1 发送。
- 复用仪表已有媒体/窗口接口，验证中央 640×240 小窗口；原仪表 HMI 保留。
- 0.4.4 修复操作锁残留、跨会话 TCP 源端口复用和重复 NCM 重连。
- 实车已有首次动态画面与新版9次重复连接记录；**传输通过、画面观察和Host实际恢复是不同验收项**。
- 0.5.0增加前台Service拥有的最长30分钟会话、通知停止、有界日志；切导航不再由Activity取消长会话。采集传输真实编码PTS，不保存持续视频。
- 长模式先协商DCV1/2；0.4.x仪表接收端会在START前拒绝。0.6.0继续使用0.5.0仪表App，已安装该版本无需重刷仪表，只需同签名覆盖APK。
- 0.6.0增加完整画面保持比例、中心裁剪、自定义地图区域及原拉伸对照；配置按会话冻结，保留为历史几何候选。
- 0.7.0将持续投屏的车机硬件 AVC/DCV1 几何提升为1920×720/30 FPS请求，并在DCV1发送前按编码PTS限流；仪表App只改高清几何槽和720行AVC边界，MCU、参考OS、USB角色脚本和停止机制保持不变。
- 0.7.1在发送端保留PTS选帧并将接受帧重定时到固定33,333微秒传输节奏；APK升为code18，仪表二进制逻辑沿用0.7.0高清适配。
- 0.7.2将Surface输入编码器无新画面时的上一帧重复 cadence 对齐到33,333微秒，并保留0.7.1的PTS选帧/重定时；APK升为code19，必须与匹配的0.7.2高清仪表App成对使用。该机制维持静态画面节奏，不制造运动画面。
- 0.7.3在连续采集转发前校验MediaCodec实际输出格式必须为1920×720；输出格式缺失或尺寸不符会立即失败。APK升为code20，必须与匹配的0.7.3高清仪表App成对使用；该门控不替代QNX解码和实际显示验收。
- 0.7.4在采集结束时记录编码PTS FPS、输出墙钟 FPS和平均PTS间隔，便于实车区分编码器真实节奏与DCV1重定时。APK升为code21，必须与匹配的0.7.4高清仪表App成对使用；统计不替代QNX解码和实际显示验收。
- 0.7.5在DCV1发送前按单调时钟排程33,333,333纳秒一帧，防止接受帧成束发送；慢ACK不追赶发帧，记录`FRAME_PACER`迟到与实际传输间隔。APK升为code22，必须与匹配的0.7.5高清仪表App成对使用；传输节奏统计不替代QNX解码和实际显示验收。
- 0.7.6修复慢ACK超过一个帧周期后的排程重锚定：迟到后下一帧从当前实际发送起点重新等待33,333,333纳秒，避免沿用旧deadline形成追赶突发。APK升为code23，必须与匹配的0.7.6高清仪表App成对使用；仪表接收端沿用0.7.5已审计二进制，传输节奏统计不替代QNX解码和实际显示验收。
- 0.7.7在`FRAME_PACER`中记录最小/最大实际发送间隔和`burst_intervals`，并拒绝发送之间的单调时钟倒退；APK升为code24，必须与匹配的0.7.7高清仪表App成对使用。仪表接收端沿用0.7.5已审计二进制，发送端指标不替代QNX解码和实际显示验收。
- 0.7.8新增`OutputFrameRateEvidence`：自然结束且请求至少3秒时，编码器需输出至少60帧，并通过PTS/墙钟28.5～31.5 FPS及PTS间隔门控；APK升为code25，必须与匹配的0.7.8高清仪表App成对使用。`SHELL_CAPTURE_FPS_GATE`只代表Android编码输出，不替代QNX解码和实际显示验收。
- 0.7.9将G3按钮接入APK自带的Surface AVC入口，独立运行5秒1920×720硬编门控；连续过程中每60个编码器输出图像滚动检查PTS/墙钟30FPS，要求`SHELL_CAPTURE_CODEC`、实际格式、FPS门控、自然结束和SPS/PPS/IDR证据。APK升为code26，必须与匹配的0.7.9高清仪表App成对使用；这些证据仍不替代QNX解码和实际显示验收。
- 0.8.0增加远程副屏目标选择和独立探针：APK列出可启动应用，shell侧创建1920×720 public/presentation `VirtualDisplay`，用`am start --display`启动选择的组件，编码输出继续进入既有DCV1/NCM/QNX链路；“车机主屏”仍是默认回退路径。仪表OS、MCU、App接收器、USB角色脚本和DCV1协议不改；APK为code27，车机VirtualDisplay/跨屏启动必须先通过现场日志门控。
- 固件KZB已确认存在中央动态告警节点的本地几何；不能宣布中央小窗是全状态安全区。**本版未实现告警隔离，只允许停稳/台架验证**，勾选确认不等于安全认证。
- 0.6.0新几何仍需停稳实显验收；0.5.0首轮176.890秒主动停止、次轮10.687秒，两轮清理通过，但10/30分钟、自然到时及异常场景未覆盖。

## 构建与使用

APK需要JDK21、Android SDK35、build-tools35.0.1；Java语言目标11，目标车机Android10/API29。依赖版本承接0.4.4，没有同时升级工具链或重写Kotlin。

```bash
cd phase1/android
bash gradlew testDebugUnitTest assembleDebug lintDebug --console=plain
```

Windows使用`gradlew.bat`。首次需要网络下载依赖；`--offline`只适合已准备好缓存的环境。完整说明：[构建](docs/BUILD.md)、[停稳验证顺序](docs/USAGE.md)。

**新环境产生的debug签名可能不同，不能保证覆盖安装原实测APK。不要为覆盖安装而公开旧签名密钥，也不要盲目卸载清数据丢失ADB身份。**
